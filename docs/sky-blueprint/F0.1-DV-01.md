# F0.1 / DV-01 — sky-ai Worker

Source of truth: Notion "Sky AI v1.0" → 07 — ফেজ রোডম্যাপ, task F0.1.

## Goal
All `/api/ai/*` traffic goes through a new `sky-ai` Worker via a Service
Binding from `admission-gk`, with **identical behaviour** for students.
Fixes BUG-DV-001 (admission-gk is full at 64 variables).

## Steps
1. **(this PR)** `sky-ai/` skeleton: `/health` only, tests, manual deploy
   workflow `sky-ai-deploy.yml`. admission-gk is NOT touched → zero student impact.
2. Run `sky-ai-deploy.yml` (DEPLOY) and confirm
   `https://sky-ai.admissionhub.workers.dev/health` answers `"service":"sky-ai"`.
3. Add to admission-gk `wrangler.toml` (bindings do not count toward the
   64-variable limit):
   ```toml
   [[services]]
   binding = "SKY_AI"
   service = "sky-ai"
   ```
   and forward only `GET /api/ai/sky-health` → `env.SKY_AI.fetch(...)` with
   header `x-sky-ai-caller: admission-gk`. Existing AI routes unchanged.
4. Move AI code (agentChat, status, prefs, …) into sky-ai route by route,
   each behind a kill switch (F0.2 feature flag / canary), `/api/ai/chat` last.

## Done (F0.1)
Students see no difference, every `/api/ai/*` request is served by sky-ai,
rollback = flip the flag back to admission-gk.
