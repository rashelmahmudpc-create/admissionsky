# F0.8 — রিপো পরিচ্ছন্নতার তালিকা (Repo Cleanliness List)

Source of truth: Notion "Sky AI v1.0" → main page, checklist item
`F0.8: রিপো পরিচ্ছন্নতার তালিকা`. Blueprint page:
<https://app.notion.com/p/3fe578b86589812da119f975cdf1881a>

Measured against `main` = `85a81fd` on 2026-10-31.

This is a **list, not a deletion**. Everything below is evidence a human
decides on; nothing here is removed without the owner's word. The point of the
phase is that the repo's mess is now *named and bounded*, and that the objective
part of it cannot grow back — see `repo-cleanliness.test.mjs`, which fails the
build when a new temp file, an unnamed workflow, or a fresh orphan file appears.

## 1. What "clean" means here (the four rules the guard enforces)

1. **No temp/junk files tracked.** `.log .tmp .bak .orig .swp .DS_Store`,
   `node_modules/`, and any `.env` must never be committed. `.gitignore`
   already covers the build/scratch directories (`node_modules/`, `dist/`,
   `.wrangler/`, `.agent_tmp/`).
2. **Every workflow has a `name:`.** An unnamed workflow shows up in the
   Actions list as its file path, which is how a run gets ignored.
3. **No new orphan source file.** A root-level `.js`/`.mjs` file that no other
   tracked file mentions is dead code. Two exist today and are on the list
   below; a *third* is a build failure.
4. **A one-shot ops workflow never fires by itself.** A workflow whose job is
   "apply/revert/set/rotate/wipe/backfill/bootstrap" must be `workflow_dispatch`
   only — it must never be reachable from `push`, `pull_request` or `schedule`.

## 3. The list — what to decide, in priority order

### 3.1 Two orphan files (a human decision, not a delete)

- `exam-center-sky.js` (7 lines) — **keep.** A deliberate no-op stub: the exam
  centre was rolled back 2026-10-18, but Cloudflare Pages keeps serving the
  deleted path and an installed service worker can still request it. Deleting
  it makes a stale shell crash on `#dots`. Its own header says
  "do not delete without bumping `sw.js` BUILD_ID first". It is unreferenced *by
  design*, so it sits in the guard's allowlist with that reason attached.
- `vocabulary-range-cleanup.js` (128 lines) — **candidate to remove.** A
  one-time, scope-locked PWA migration (question range 101–547) that has already
  run on the installed app. Nothing references it any more. Awaiting the
  owner's OK to delete.

### 3.2 Branch hygiene — the biggest single win

131 remote branches against 1 open PR. 35 are already merged into `main` and
are pure clutter in every branch picker and every `git branch -r`. Proposed:
delete the merged 35 in one pass, then review the 94 unmerged ones in batches —
some are old `claude/`, `cline/`, `arena/` scratch branches that will never
merge. **Nothing is deleted until the owner says so.**

### 3.3 One-shot ops workflows that could be archived

54 workflows are `workflow_dispatch`-only, and 15 of them are named for a
one-time operation that has already happened — `apply-release-pins-20261018`,
`fresh-start-wipe-20261017`, `revert-unified-theme-20261016`,
`deploy-profile-v2-20261016`, `ai-kv-name-fix`, `ai-model-fix`, the three
`ai-key-set*`, the three `voice-*-secret*`, `bind-otp-b-worker-secrets`. They
are harmless (manual-only, rule 4 holds) but they are noise in the Actions list.
Proposed: move the ones older than 30 days to an `archive/` folder or delete
them, keeping the ones the owner still uses.

### 3.4 Root-level document sprawl

23 `.md` files at the repo root, many of them QA notes from one phase
(`PHASE1_QA_NOTES`, `SUPER_UPGRADE_QA`, `VOCABULARY_CARD_FLASH_QA`,
`STARTUP_LOADING_QA`, `MINDPAL_QA_NOTES`, `COURSE_REMOVAL_QA`,
`OFFLINE_PERFORMANCE_QA`, `experience_studio_runtime_findings`, `todo.md`).
`docs/` already holds 77 `.md` files and `AGENT_RESUME/` holds 68. Proposed:
move the finished QA notes under `docs/qa/` so the root holds only the files a
new agent must read (`AGENTS.md`, `CLAUDE.md`, `RESUME_STATE.md`).

### 3.5 Large tracked binaries (context, no action yet)

`course-assets/sandhi/sandhi-master-guide.pdf` (4.4 MB),
`worker-bundle.mjs` (1.6 MB, generated), `mcq_final.json` (944 KB),
`result-analysis-500.js` (636 KB), the `tests/visual/baseline/*.png` set. The
visual baselines are needed by the visual guard; the PDF is course content. No
change proposed — recorded so the next size review has the numbers.

## 4. What this phase deliberately does NOT do

- **No deletion without the owner's approval.** Every item above is a proposal.
- **No `git filter-repo` / history rewrite.** It would break every open PR and
  the deploy pins, for no benefit the list can measure.
- **No branch deletion.** 35 merged branches are the obvious cleanup, but
  deleting refs is not reversible by an agent and is the owner's call.
